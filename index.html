TECHNICAL CHALLENGES
01
검색 트래픽 집중 — Elasticsearch 도입으로 p95 31% 개선
문제JPA LIKE는 앞 와일드카드로 인해 Full Table Scan — 트래픽 집중 시 성능 저하
해결GIN 인덱스로 12% 개선했으나 실패 14건 발생, 수치로 한계 검증 후 ES 도입. nori + fuzziness:AUTO로 한국어 검색 품질 동시 확보
p95 1,879ms → 1,294ms · 실패율 0% · 데이터 100배 증가 시 응답 지연 증가율 ES +85% vs DB +153% (ES 확장성 우위 확인)
아키텍처
02
ES Dynamic Mapping nori 누락 — @PostConstruct 초기화 순서 보장
문제Kafka consumer가 인덱스 초기화보다 먼저 실행되어 nori 빠진 매핑이 디스크에 영속화 — 재시작해도 복원 불가
해결ApplicationRunner는 Kafka 시작 순서 보장 불가 → @PostConstruct로 전환, bean 생성 시점에 인덱스 초기화 선행 보장
명시적 매핑 선생성으로 Dynamic Mapping 차단 · 재발 방지 설계
아키텍처
03
ES 단일 장애점(SPOF) 제거 — Resilience4j 서킷 브레이커 + Fallback
문제socket-timeout 미설정으로 ES 장애 시 스레드가 무한 대기 → 서비스 전체 성능 저하
해결socket-timeout 2s로 선제 차단 후 @CircuitBreaker 적용, 장애 감지 즉시 PostgreSQL fallback 전환. 카오스 테스트로 CB 상태 전이 검증
장애 중 실패율 0% (카오스 테스트 기준) · 최대 지연 3,259ms → 2,000ms 단축
아키텍처
04
MSA 데이터 정합성 — Outbox 패턴으로 이벤트 원자적 발행 보장
문제MSA 환경에서 글로벌 트랜잭션 불가 — Kafka 발행 실패 시 DB는 변경됐으나 이벤트 미발행으로 데이터 불일치 발생
해결동일 트랜잭션 안에 outbox_events 저장으로 원자적 처리, 스케줄러 1초 폴링으로 재발행. FOR UPDATE SKIP LOCKED으로 중복 발행 방지, DLQ로 문제 메시지 격리
트랜잭션 내 원자적 저장 · Kafka 재기동 후 자동 재발행
아키텍처
05
ES 색인 컨슈머 자연 멱등성 — 별도 인프라 없이 이중 색인 0건
문제Outbox 재처리로 같은 메시지가 중복 발행될 수 있는 at-least-once 환경에서 이중 색인 위험
해결ES의 동일 document ID 재색인 시 upsert, deleteById 부재 시 무시되는 자연 멱등성 분석·활용. processed_events 테이블 없이 추가 인프라 0으로 해결
이중 색인 0건 · 추가 인프라 비용 없음

TECHNICAL CHALLENGES
01
동시 출석 등록 Race Condition — DB Unique 제약으로 중복률 0% 달성
문제여러 관리자가 동시에 동일 인원 출석 등록 시 중복 저장 — 애플리케이션 단 검증만으로는 Race Condition 차단 불가
해결@Column(unique=true)로 DB 레벨 INSERT 직렬화, DataIntegrityViolationException → IllegalStateException 변환. 동명이인은 차단 대신 분기 안내로 누락 방지
데이터 중복률 0% · 무결성 100%
아키텍처
02
전체 인원 일괄 갱신 1+N 쿼리 — JPA 벌크 연산으로 N회 → 1회 단축
문제JPA 기본 메서드는 SELECT 1회 + UPDATE/DELETE N회로 동작 — 전체 인원 일괄 갱신 시 1+N 쿼리 발생
해결@Modifying(flushAutomatically=true) + 커스텀 JPQL로 영속성 컨텍스트 우회, DB에 단일 쿼리 직접 전송
쿼리 실행 횟수 N회 → 1회
아키텍처
03
소그룹 편성 자동화 — 다중 필터링 기반 랜덤 알고리즘 구현
문제매주 수동 편성으로 관리자 리소스 소모 및 인적 편향 개입 가능
해결isExcluded·isHard 기반 2단계 필터링 후 특수 인원 균등 선배치 → 일반 인원 라운드로빈 + Collections.shuffle(). 파이프라인 구조로 신규 조건 추가 시 확장 용이
수동 편성 → 클릭 1회 자동화 · 편성 공평성 기술적 보장
